# relinker

## change [wide-store decoder]

- `--to-rosetta` lowers an unaligned 256-bit VMOVUPS, VMOVUPD or VMOVDQU store whose effective address uses 32-bit addressing through a base or index ([wide-store decoder](../../../core/relinker/codegen/src/x86/WideStoreOperands.cpp)): it materializes the effective address once into RAX with a 32-bit-addressed LEA inside the spill scaffold it shares with the masked-store lowering, then stores the two 128-bit halves from that register at offsets 0 and 16 with 64-bit addressing, so an effective address near 4 GiB keeps its upper half above 4 GiB instead of wrapping. The scaffold saves RFLAGS, RAX and RCX in the 24 bytes at `[RSP-152,RSP-128)`. Unindexed 32-bit stack operands whose 32-byte store overlaps those slots throw; all indexed 32-bit RSP-based operands are now rejected conservatively because their runtime index could alias the slots. The SysV red zone covers only the 128 bytes immediately below the full-width RSP; a `67`-prefixed operand computes a zero-extended 32-bit effective address, so that red-zone rule alone cannot prove non-aliasing when the guest stack is in the low 4 GiB. This restriction applies only to the materialized 32-bit-address path; ordinary 64-bit RSP-indexed stores remain on the split path. EIP-relative and 32-bit absolute addressing keep the split, and a 32-bit absolute store whose upper-half address crosses the address boundary still throws. No affected title and no Rosetta execution of this case has been verified.
